## 2026-08-19 最终恢复：CloudBase `010`

本复盘中的 503、资源隔离、版本 `009` 和 SCF 临时入口均为历史阶段。当前国内主站
已经恢复到 CloudBase：

- 新账期资源隔离解除，发布前只读用量为 2.31 / 3000 点。
- 从当时已验收的应用快照制作干净发布包并发布版本 `010`。
- 体验版不支持免费手动灰度，因此在完整本地验证后使用“发布并自动切流”。
- 公网出站开启；私有网络关闭；服务端口 `3000`。
- 自动启停，自定义最小实例 `0`、最大实例 `1`，无定时扩缩容。
- 首页和 `/analysis` 均为 HTTP 200。
- 有效 API POST 返回 `source=real-ai`、`provider=modelscope`、
  `errorCategory=null`。
- 真实浏览器点击显示“真实 AI 生成”和“模型服务：ModelScope”，未进入 Mock fallback。

本次恢复证明历史故障由多层原因组成：7 月额度耗尽造成 503；旧版本公网出站配置和
ModelScope 输出波动影响真实 AI；体验版发布能力又限制了切流策略。排障必须分别验证
资源、容器网络、Provider、接口结构和浏览器路径，不能只依据控制台“正常”状态。

当前操作以 [DEPLOYMENT_HANDOFF.md](DEPLOYMENT_HANDOFF.md) 为准。以下内容保留为
历史证据，不代表当前线上状态。

## 2026-07-31 补充：CloudBase 免费额度隔离

本次国内站 503 与 7 月 15 日的 ModelScope 超时、7 月 30 日的结构化解析回归
不是同一类故障。

CloudBase CLI 只读检查确认：

- 环境仍为体验版且状态 normal，服务也显示 normal、允许公网访问。
- 当时账期为 2026-07-11 至 2026-08-11。
- 套餐内 3000 点已全部用完，总计量 3049.31 点。
- 云托管消耗 3038.91 点，主要来自 CPU 1401.68 点和内存 1631.03 点。
- 首页和 `/analysis` 均返回 HTTP 503。
- 当时包含瞬时失败重试增强的灰度部署被平台以资源隔离拒绝，没有产生新版本和流量
  变更；切换前提交标识只在 Private archive 保留。

因此本次直接根因是免费体验额度耗尽。环境和服务列表中的 normal 只表示资源对象
仍存在、配置未被删除，不代表隔离状态下可以启动容器处理请求。

在不付费的边界下，恢复方式是等待 2026-08-11 账期刷新后重新检查。免费环境按
官方当时规则不支持加购资源包或开启超限按量。等待期间保留 CloudBase 配置和
历史版本，当时以 Netlify 作为公开备用站；不得通过最小实例 1 或持续探活消耗下个
周期额度。

## 2026-07-30 补充：结构化解析间歇性回归

7 月 15 日版本 `009` 的恢复证据仍然有效，但 7 月 30 日复测发现新的间歇性
问题：一次直接公网 API 在 9.16 秒返回 `real-ai / modelscope / null`，紧接着
浏览器真实点击又降级为 `mock-fallback / modelscope / provider_error`。

这说明当时 Token、网络出口和 30B 模型路径并非永久不可用；问题集中在免费
ModelScope 输出形态会波动，而已发布解析器容错不足。本地已增强 JSON、字段变体、
content 数组、thinking block、代码围栏和六段 Markdown 的兼容能力，但尚未通过
CloudBase 灰度发布。线上不能宣称稳定恢复，直到增强版本连续通过接口和浏览器验证。

## 事件结论

2026-07-15 复测时，国内 Demo 并非持续宕机。首页、`/analysis`、CloudBase 容器和 API route 均可访问；真实故障是 ModelScope 调用在 30 秒窗口内没有完成，页面随后诚实降级为 Mock fallback。

同时，CloudBase 使用平台默认域名、自动扩缩容最小实例为 0。低流量后实例会被回收，首次访问存在冷启动；控制台也明确提示默认域名仅适合开发测试，存在频率、功能和稳定性风险。这会让用户把慢启动或短时不可用误解为“网站崩了”。

## 恢复结果

CloudBase 版本 `009` 已完成全量发布并承载 100% 流量。公网首页与 `/analysis` 均为 HTTP 200；真实 API 在 11.83 秒返回 `source=real-ai`、`provider=modelscope`、`errorCategory=null`，包含 6 个章节和 4 条假设。真实浏览器点击在 14.57 秒完成，页面显示 `Real AI 生成` 和 `Provider: ModelScope`，没有出现 Mock fallback、页面错误或控制台错误。

运行时代码将已知的旧 235B 模型配置迁移到 `Qwen/Qwen3-30B-A3B-Instruct-2507`，其他显式模型配置仍然优先。这样无需为了改模型名重新打开会展示普通环境变量的 CloudBase 配置页。

## 现场证据

- CloudBase 版本：`008`
- 运行状态：正常
- 流量：100%
- 实例：1
- 首页与 `/analysis`：可打开，无前端控制台错误
- 首次首页访问：约 6 秒
- 真实生成：约 40 秒后返回 Mock fallback
- UI 结果：`Provider: ModelScope`、`网络错误`

- CloudBase 公网出站：开启
- ModelScope 官方 endpoint：从独立网络使用无效测试 Token 可在约 2 秒内返回 HTTP 401，说明 endpoint 本身可达

## 根因判断

### 1. Real AI 故障

直接触发因素是 ModelScope 请求超过 30 秒，被 `AbortSignal.timeout` 终止。旧代码把超时和 DNS/TLS/网络异常都归类为 `network_error`，因此界面没有准确暴露真实原因。

当时线上模型为 `Qwen/Qwen3-235B-A22B-Instruct-2507`。这是 235B 级大模型，而 ModelScope API-Inference 是动态额度、动态并发、非 SLA 的免费体验服务。大模型在平台繁忙时更容易排队或超出 30 秒。

### 2. “网站崩了”的感知

CloudBase 当时最小实例为 0，低流量时会缩容。下一次请求必须重新启动容器；再叠加默认域名的开发测试稳定性边界，用户可能在首次访问时看到长等待或暂时失败。

## 已实施的本地修复

- 推荐默认模型调整为 `Qwen/Qwen3-30B-A3B-Instruct-2507`，降低推理资源和延迟。
- ModelScope 输出上限从 1800 降为 1600 tokens，保留 6 个结构化章节的同时减少完成时间。
- 新增 `timeout` 错误分类，界面显示“服务超时”，不再把超时误报为普通网络错误。
- 保留 Mock fallback，确保外部模型不可用时产品流程仍可演示。

## 线上修复步骤

2. 已发布版本 `009` 并确认 100% 流量切换。
