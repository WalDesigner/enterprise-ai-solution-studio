更新：2026-09-23；修复提交 `b794c53` 已发布为 CloudBase `013`，正常 / 100% 流量；公网浏览器真实生成已通过。

## 为什么“之前解决过”又出现

兜底是统一的降级表现，不是唯一故障。历史问题包括慢模型超时、输出解析差异、瞬时网络错误和 CloudBase 资源隔离。本次生产请求到达模型服务，但收到 HTTP 400；不能认定同一根因复发。

旧实现有两项维护短板：模型目录可以在应用未发布时变化；错误分类把 400/404/422 合并，导致参数不兼容与模型不可用难以区分。结果页面使用同一套绿色结果框，也弱化了模拟来源提示。

官方当前 [Qwen3.5-35B-A3B 页面](https://www.modelscope.cn/models/Qwen/Qwen3.5-35B-A3B) 提供托管 API 示例。修复采用该默认模型及非思考参数，本地实际浏览器生成 17.6 秒成功。旧模型页未显示同样的托管入口只是线索，不足以单独证明停服；未获取历史 400 的细分正文，不能编造确定原因。

## 故障处理表

| 类别 | 维护动作 | 不应采取的动作 |
| --- | --- | --- |
| 模型不可用 | 核对当前 API 目录和账号访问范围，选受支持模型后验收 | 无限重试旧模型 |
| 参数不兼容 | 核对模型、思考模式与协议，有限单次验证 | 直接认定密钥失效或购买云资源 |
| 认证失败 | 由负责人检查权限或轮换密钥 | 把密钥贴到聊天、日志、截图或 Git |
| 模型额度不足 | 查看模型账户周期额度；必要时经确认更换服务 | 把 CloudBase 资源点当模型额度 |
| 频率受限 | 停止连点，等待限制窗口；区分应用与模型限流 | 密集压测或无界重试 |
| 超时、网络、5xx | 原有总 30 秒、最多两次尝试边界内恢复；核查网络与供应商状态 | 无限重试、切断本机连接 |
| 解析失败 | 核对输出与六章节契约，使用离线样本回归 | 把不完整输出标成功 |

## 验收与诚实边界

- 页面 HTTP 200、API HTTP 200 或“有文字”均不足以验收真实 AI。
- 必须确认 `source=real-ai`、`provider=modelscope`、`errorCategory=null`，以及完整六章节。
- 自动回归中的模拟响应只证明应用行为，不证明外部模型健康；真实验收另行记录。
- 9 月 23 日实际浏览器点击生成，保存时间更新至 13:49，返回新六章节方案，显示“真实 AI 生成 / ModelScope”，无错误标签。没有再次直接 POST，也未单独抓取原始响应；不把 UI 验证夸大为原始 JSON 抓包。
- 新增错误分类、模拟结果失败提示、持久化及手机回归，没有为了“永不报错”隐藏故障。
- 单个免费供应商无法保证永久可用。当前修复降低已知故障复发及定位成本，不等于高可用 SLA。备选 Provider 代码存在不代表已配置或验证自动切换。
